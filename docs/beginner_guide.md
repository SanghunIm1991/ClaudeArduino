# 組み込み開発 入門ガイド（初心者向け用語解説）

## この資料について

このプロジェクト（[概要資料](overview.md)、[プログラム①](../programs/01_serial_only/README.md)〜[プログラム③](../programs/03_night_light/README.md)）を読む上で前提となる、電気・Arduino・組み込みプログラミングの基礎用語をまとめたものです。各プログラムのREADMEは前提知識がある読者向けに書かれているため、初めて読む場合はまず本資料に目を通すことを推奨します。

範囲は、①〜③で実際に登場した用語に加え、今後の拡張で登場しうる基礎知識（割り込み・I2C/SPI通信・EEPROM等）も含めています。後者はこのプロジェクトではまだ未使用です。

## 1. 電気の基礎

### 電圧・電流・抵抗

| 用語 | 意味 | 単位 |
|---|---|---|
| 電圧（Voltage） | 電気を流そうとする力の大きさ。水で例えると「水圧」に近い | V（ボルト） |
| 電流（Current） | 実際に流れる電気の量。水で例えると「水量」に近い | A（アンペア）、回路内では mA（ミリアンペア＝1/1000A）単位もよく使う |
| 抵抗（Resistance） | 電流の流れにくさ。水で例えると「水道管の細さ」に近い | Ω（オーム） |

### オームの法則

電圧・電流・抵抗の関係を表す最も基本的な式。

```
電圧(V) = 電流(I) × 抵抗(R)
```

回路設計でよく使うのはこれを電流について解いた形（例: [プログラム②](../programs/02_switch_led/README.md)のLED回路計算）。

```
電流(I) = 電圧(V) ÷ 抵抗(R)
```

例えば「5V電源に1kΩ抵抗をつなぐと何mA流れるか」は `5V ÷ 1000Ω = 0.005A = 5mA` と計算できる。LEDの電流制限抵抗は、この式でLEDに流れる電流がLEDの定格（一般的に数mA〜20mA程度）に収まるよう決める。

### GND（グラウンド）

回路の電流が最終的に戻ってくる基準点（0V）。「アース」「グランド」とも呼ばれる。Arduinoの場合はボード上の `GND` ピンがこれにあたり、すべての回路はどこかでGNDに接続されている必要がある。

### プルアップ抵抗・プルダウン抵抗

デジタル入力ピン（後述）は、何もつながっていない状態（オープン）だと電圧が不安定になり、HIGH/LOWの判定が定まらない（ノイズを拾ってチラつく）。これを防ぐため、スイッチが押されていないときの電圧を確定させる抵抗を入れる。

- **プルダウン抵抗**: 入力ピンをGND側に抵抗で軽く引っ張っておく方式。スイッチを押していないとき入力はLOW、押すとHIGHになる。[プログラム②](../programs/02_switch_led/README.md)・[③](../programs/03_night_light/README.md)で採用。
- **プルアップ抵抗**: 逆に電源側（5Vなど）に引っ張っておく方式。押していないときHIGH、押すとLOWになる（Arduinoには内蔵プルアップ機能もあるが、本プロジェクトでは外付け抵抗によるプルダウン方式で統一している）。

### 直列・並列

複数の部品のつなぎ方。**直列**は一本の道を順番につなぐ方式（電流はどこでも同じ）。**並列**は枝分かれさせて複数の道を並べる方式（各枝に電圧は同じだが電流は分かれる）。[プログラム③](../programs/03_night_light/README.md)のLED駆動回路では、赤・白・緑の3灯を並列に配線し、それぞれ個別の電流制限抵抗を直列に挟んでいる。

## 2. Arduinoの基礎

### マイコン（マイクロコントローラ）

CPU・メモリ・入出力機能を1チップに集積した小型のコンピュータ。Arduino Unoに搭載されているマイコンは **ATmega328P**。パソコンのようにOSを起動するのではなく、書き込んだプログラム（スケッチ）を電源投入直後から単独で実行し続ける。

### GPIO（汎用入出力ピン）

General Purpose Input/Output の略。ソフトウェア側の設定で入力にも出力にも使える汎用のピン。Arduino Unoの `D0`〜`D13`（デジタルピン）・`A0`〜`A5`（アナログ入力兼用ピン）がこれにあたる。

### デジタル入力・デジタル出力

デジタルピンは基本的に **HIGH（約5V）** と **LOW（約0V）** の2値しか扱わない。

- **デジタル入力**（`digitalRead()`）: スイッチが押されているか（HIGH）いないか（LOW）などを読み取る。[プログラム②](../programs/02_switch_led/README.md)のスイッチ判定で使用。
- **デジタル出力**（`digitalWrite()`）: LEDを点灯（HIGH）・消灯（LOW）させるなど、ピンから電圧を出力する。[プログラム②](../programs/02_switch_led/README.md)のLED制御、[③](../programs/03_night_light/README.md)のMOS-FETゲート駆動で使用。

### アナログ入力

デジタルと異なり、電圧を連続的な数値として読み取る機能（`analogRead()`）。Arduino Unoでは0〜5Vの電圧を0〜1023の整数値に変換する（10ビットADC）。[プログラム③](../programs/03_night_light/README.md)ではCdSセルの分圧回路の電圧を `A0` で読み取り、明るさの目安として使っている。

### PWM（Pulse Width Modulation／パルス幅変調）

Arduinoのデジタル出力ピンの一部（`~`マーク付きのピン）は、HIGH/LOWの2値ではなく、高速にON/OFFを繰り返す比率（デューティ比）を変えることで疑似的にアナログ的な出力（LEDの調光やモーターの速度制御など）を実現できる。`analogWrite()`で使う。[プログラム③](../programs/03_night_light/README.md)のD9はPWM対応ピンを割り当てているが、現在の実装ではON/OFFのみに使用しており、将来の調光機能への拡張余地として残している。

### シリアル通信・ボーレート

Arduinoとパソコンなどの機器間で、1本の信号線を使って1ビットずつ順番にデータをやり取りする通信方式。USBケーブル経由でPCとやり取りする際にも使われる（[プログラム①](../programs/01_serial_only/README.md)）。

**ボーレート（baud rate）** は通信速度の設定値（単位: bps=bits per second）。送受信側で同じ値に揃える必要がある。本プロジェクトでは9600bpsを共通で採用（[プログラム①](../programs/01_serial_only/README.md)で選定根拠を記載）。

## 3. 電子部品

### LED（発光ダイオード）と順方向電圧（Vf）

電流を流すと光る半導体部品。極性があり、長い足（アノード）を電源側、短い足（カソード）をGND側につなぐ。LEDは一定以上の電圧（**順方向電圧 Vf**、色によって異なりおおむね1.8〜3.4V程度）をかけないと光らず、逆にVfを超えた分の電圧がそのまま抵抗にかかる。電流制限抵抗の値は、オームの法則で「電源電圧−Vf」を許容電流で割って決める（詳細は[プログラム②の電圧・電流計算](../programs/02_switch_led/README.md)）。

### 抵抗器とカラーコード

電流を制限する部品。本体に塗られた色の帯（カラーコード）で抵抗値を読み取る（例: 茶黒赤金＝1kΩ、茶黒橙金＝10kΩ）。抵抗に極性はなく、どちら向きに接続してもよい。

### タクトスイッチ

押している間だけ内部の接点が導通する（電気が流れる）小型のスイッチ。離すと元に戻る。[プログラム②](../programs/02_switch_led/README.md)・[③](../programs/03_night_light/README.md)で使用。

### CdSセル（光導電セル／照度センサ）

硫化カドミウム（CdS）を使った、光の強さによって電気抵抗が変化する部品。**明るいほど抵抗値が小さく、暗いほど抵抗値が大きくなる**特性を持つ。単体では「抵抗値」しか変化しないため、他の抵抗と組み合わせて分圧回路を作り、電圧の変化としてArduinoのアナログ入力で読み取る（[プログラム③](../programs/03_night_light/README.md)）。

### MOS-FET

電圧をかけるだけでON/OFFを切り替えられる電子スイッチ部品（トランジスタの一種）。ゲート（G）・ドレイン（D）・ソース（S）の3本の端子を持つ。ゲートにしきい値以上の電圧をかけるとドレイン-ソース間が導通する。Arduinoの1本のピンでは電流容量が足りない負荷（複数のLEDなど）を、GPIOではなく電源ラインから直接駆動しつつ、ON/OFFの制御だけをGPIOで行う「スイッチの中継役」として使う（詳細な採用理由は[プログラム③「MOS-FETの効果」](../programs/03_night_light/README.md)）。

### ダイオード

電流を一方向にしか流さない部品。モーターやリレーなど、コイルを含む部品（**誘導性負荷**）をMOS-FETやトランジスタでON/OFFすると、OFFにした瞬間に逆向きの高電圧（逆起電力）が発生し部品を壊すことがある。ダイオードを並列に入れてこの逆電流を逃がす使い方を**フライバック保護**と呼ぶ。LED単体（誘導性負荷でない）にはこの保護は不要（[プログラム③「ダイオードの扱い」](../programs/03_night_light/README.md)で詳述）。

### ブレッドボード

はんだ付けせずに部品同士を差し込むだけで回路を組める試作用の基板。内部で特定の穴同士が電気的につながっており、そのつながり方に沿って部品やジャンパワイヤ（配線用の電線）を配置する。

## 4. プログラミング概念

### チャタリング・デバウンス

タクトスイッチなどの機械式スイッチは、押した/離した瞬間に接点が微小に跳ね返り、電気的には一瞬の間にON/OFFが何度も切り替わる**チャタリング**という現象が起きる（[プログラム②の実測検証](../programs/02_switch_led/README.md)では約1msの間に3回反転する例を確認）。これを放置すると「1回押しただけなのに複数回押されたと誤認識する」といった不具合につながる。

**デバウンス**はこのチャタリングを取り除く処理。本プロジェクトでは、信号が変化してから一定時間（50ms）安定するまで確定させない「時間ベースデバウンス」を採用している。

### ノンブロッキング処理

`delay()`のようにプログラムの実行を一時停止する処理を使わず、`millis()`/`micros()`（起動からの経過時間を返す関数）と時刻の比較によって「時間が経過したかどうか」を判定する書き方。他の処理（スイッチ判定やセンサ読み取りなど）を止めずに複数のタイミング制御を同時に行える。[プログラム③](../programs/03_night_light/README.md)の`loop()`はこの方式で実装されている。

### ヒステリシス

ある値が1つの閾値をわずかに超えたり下回ったりするたびに出力が細かく切り替わってしまう「バタつき」を防ぐため、ON側とOFF側で異なる2つの閾値を設ける手法。[プログラム③](../programs/03_night_light/README.md)では明るさの判定に採用し、境界付近の微小な値の揺れだけではLEDのON/OFFが切り替わらないようにしている。

### 状態遷移（ステートマシン）

プログラムが取りうる状態（モード）をあらかじめ定義し、特定の入力（イベント）に応じて状態が切り替わるという考え方で処理を整理する設計手法。[プログラム③](../programs/03_night_light/README.md)の「AUTO→FORCE_ON→FORCE_OFF→AUTO」というモード切替がこれにあたる。

### 割り込み（interrupt）※本プロジェクトでは未使用

ある条件（特定ピンの電圧変化など）が発生した瞬間に、実行中の処理を一時中断して専用の処理（割り込みハンドラ）を差し込む仕組み。`loop()`内で毎回条件をチェックする方式（本プロジェクトの現行方式）に比べ、反応の即時性が高く、`loop()`側の処理が重くても取りこぼしにくいという利点がある一方、扱いを誤ると通常処理と競合するバグ（競合状態）を起こしやすく実装難度は上がる。

### I2C・SPI通信 ※本プロジェクトでは未使用

複数のセンサやモジュールをマイコンに接続する際に使われる、シリアル通信より配線数を抑えつつ多数の機器を扱える通信規格。**I2C**は2本の信号線（SDA/SCL）を複数機器で共有し、機器ごとのアドレスで区別する方式。**SPI**は4本前後の信号線を使い、より高速だが機器ごとに専用の選択線（チップセレクト）が必要になる方式。温湿度センサや液晶ディスプレイなどの外部モジュールを追加する際によく登場する。

### EEPROM ※本プロジェクトでは未使用

Arduinoに内蔵された、電源を切ってもデータが消えない小容量の記憶領域。現在の本プロジェクトの各プログラムは電源投入のたびに初期状態（AUTOモードなど）からスタートする設計だが、EEPROMを使えば「最後に選んでいたモードを覚えておいて次回起動時に復元する」といった拡張が可能になる。

## 5. 開発ツール

### PlatformIO

Arduino向けのプログラム（スケッチ）の作成・ビルド（コンパイル）・書き込み・シリアルモニタでの動作確認を行える、VS Code拡張機能ベースの開発環境。Arduino公式のArduino IDEの代替として使われることが多い。

### ビルド・アップロード（書き込み）

**ビルド**は、人間が書いたプログラムのソースコード（`.cpp`ファイル）を、マイコンが実行できる機械語に変換する作業（コンパイル）。**アップロード（書き込み）**は、ビルドで生成したプログラムをUSBケーブル経由でArduino本体のメモリに転送する作業。PlatformIOのUploadボタン、またはCLIの`pio run --target upload`で行う。

### シリアルモニタ

Arduinoがシリアル通信で送ってくるデータ（`Serial.println()`などで出力した文字列）をPC側の画面で確認するツール。ボーレートを送信側と合わせる必要がある。プログラムの内部状態（センサの読み取り値など）を確認するデバッグ手段としてよく使う。

### COMポート

WindowsがUSBシリアル接続の機器に割り当てる番号（例: `COM3`）。Arduinoを差すUSBポートを変えたり、PCを再起動したりすると番号が変わることがあるため、書き込み時にエラーが出た場合は`pio device list`で現在の番号を確認する。
